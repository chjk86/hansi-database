# 2025_munzip_title_text_ver(2) — 한국문집총간 한시 2025판 속편 (#0664~#1259)

한국고전번역원 한국문집총간(고전종합DB `ITKC_MO_0NNNA`)의 詩類 기사를 **한 행에 한 수**씩 담은 텍스트판이다. 본편(#0001~#0663)과 같은 형식이며, 이 폴더에는 속편 581파일 218,960수가 있다(2026-09-15).

## 확인 범위 — 중요

- **#0664~#0801(138파일)은 연구자가 전 구간 확인한 자료다.** 연구자 검수본에 공식 XML을 기사 단위로 맞춘 판이다.
- **#0802~#1259(443파일)는 아직 확인이 끝나지 않은 자료다.** 공식 XML에서 통째로 재생성한 뒤 스크립트로 정련(본문에 붙은 여러 수 분할, 기사 단위 재분절, 序·원주·표지 삭제)하고 일부만 손으로 고쳤다. 연작 분할·序·주석이 있는 시는 잘못 나뉜 행이 남아 있을 수 있으니 인용·통계에 쓸 때 원문(고전종합DB)과 대조한다.

## 파일과 형식

- 파일명 `0NNN.문집명.txt` — NNN은 문집총간 번호(= ITKC id `ITKC_MO_0NNNA`). 파일 순서가 곧 문집총간 순서다. 2024년판 파일이 없던 문집은 여기에도 없다.
- 인코딩 UTF-8(BOM 없음), 줄바꿈 LF, 마지막 행 뒤 개행 있음, 빈 행 없음.
- 행 형식: `<title>제목</title>,<text>본문</text>`. 본문의 구(句)는 `。`로 끝난다.

```
<title>次寄姜復泉子久 鶴年</title>,<text>遷次君無宅。懷安我有居。何時山水處。高棟接茅廬。</text>
<title>次寄姜復泉子久 鶴年 其二</title>,<text>西塞軍麾滿。生靈未奠居。風塵無息日。吾敢愛吾廬。</text>
```

## 제목 규칙

- 연작(連作)은 `제목`, `제목 其二`, `제목 其三` … 로 한 수씩 나눈다. 첫 수에는 번호가 없다. `又`로 이어지던 연작도 `其二…`로 통일했다.
- 小題(DB `<단락제목>`)는 제목 뒤에 한 칸 띄어 붙인다: `T 小題`, 이어지는 무제 수는 `T 小題 其二`.
- 제목 원주는 앞뒤 한 칸으로 감싸 그대로 둔다(`次寄姜復泉子久 鶴年`).
- 단락 끝의 韻 표지 원주(`原韻`·`次韻`·`右次○○韻`…)는 제목 뒤에 붙인다(`T 原韻`). 남의 原韻·次韻 수를 문집 저자의 시와 구별하기 위한 장치다.
- `[ ]`는 고전종합DB 편자가 보충한 제목 표기(XML판 그대로).
- 숫자는 모두 한자(`其十二`, `二十二`).

## 본문 규칙

- 본문 원주(原註)와 서문·발문·挽詞 대상 표기 등 산문 단락은 삭제했다. 賦·辭처럼 기사 전체가 산문형인 것은 그대로 두었다.
- 결자(몇 자인지 아는 빠진 글자)는 `𪚥` 한 글자로 통일했다. 원자료의 `▦`·`▣`·`□`·`■`·글자 이미지·`N字缺`이 모두 여기에 든다. 유니코드에 없는 글자도 `𪚥`.
- 몇 자가 빠졌는지 모르는 결락 표시 `缺`·`以下逸`·`以下佚`·`下失`·`本文缺`는 원문 그대로 둔다. 한 수가 통째로 없어져 `逸`·`佚` 한 글자만 남은 행도 그대로 둔다.
- 국문 시조·가사는 詩類 기사에 실린 대로 두었다. 옛한글은 사용자 영역(U+E000~) 코드다. 한시 통계에서는 한글 포함 행을 제외한다.
- 聯句의 작자 표지는 본문에서 지웠다. 聯 제목 시는 공동작이므로 작자별 분석에서 따로 다룬다.
- 본문 안의 공백은 지웠다. 남아 있는 공백은 국문 시가 행과 `缺` 표시 토큰 앞뒤뿐이다.

## 만든 과정

2024년판(기사 단위)에서 출발해 통파일 분할 → 마커·운자·점법 기반 연작 분리 → 고전종합DB 공식 XML(공공데이터포털 마스터 데이터셋)로 재생성 → 제목·번호·표지·결자 정리 → 정합성 검사·XML 대조 → 연구자 검수(#0801까지 완료) 순으로 만들었다. 결정 근거·규칙·수치·검증 기록과 정련 스크립트는 작업 저장소에 있으며 이 폴더와 함께 공개하지 않았다.

## 알려진 한계 (2026-09-15)

- #0802~#1259는 위에 적은 대로 확인이 끝나지 않았다. 스크립트가 자동 판단을 보류한 기사(XML에 없는 4언 章·雜言, 聯句 표지, 짧은 산문형 행 등)는 원래 행 그대로 남아 있다.
- 공식 XML 자체가 한 수를 둘로 나누거나 序를 시로 둔 곳은 XML을 따르지 않고 원래 행을 두었다. 반대로 XML이 여러 수를 한 단락에 둔 곳은 그대로 한 행일 수 있다.
- 글자 차이(판본 차이, 결자 복원)는 손대지 않았다. 원문과 한두 글자 다른 행이 있다.
- 파일 위치는 문집총간 번호를 따르며, 기사 순서는 XML(고전종합DB) 순서다.
