## 3. 통합 규칙

문집 폴더별로:

### 3.1 파일 선별
- 태깅 데이터 파일만: 확장자 `.txt` `.xml` `.rtf` 및 무확장. **제외**: `.hwp`, 파일명에 `원문`·`번역` 포함, `output_*.csv`, `태깅정리_*.xml`.
- `.rtf`는 텍스트 추출 후 처리. 동일 파일명 중복(예: 읍취헌유고 rtf가 2쌍씩)은 1개만.

### 3.2 파일명 파싱 → 정렬 키
각 파일에서 추출:
- **날짜 키**: `YY년도 MM월 N주차` / `MM월 N주차` / `작업 N주차` / `NN주차` / `YYYYMMDD` / `MM월 최종` / `YY년_M월`. 정규화해 정렬 가능한 튜플로. 파싱 불가 시 Drive 업로드 시각(있으면)으로 폴백, 그것도 없으면 경고 후 파일명 사전순 최후.
- **ID 구간**: `(Pxxxxx~Pxxxxx)` `(xxxxx-xxxxx)` `Pxxxxx~Pxxxxx` 패턴 → `(start, end)`.
- **작업자**: 파일명 내 인명(선택, 리포트용).
- 마커(`(수정)` `(완성본)` `최종` `최신본` `지영원수정_`)는 **정렬에 쓰지 않음**(날짜 키가 이미 반영). 리포트에만 기록.

### 3.3 통합 모드 판정
각 파일의 실제 `<Poem id>` 최소·최대를 읽어 판정:
- 문집 전체 ID 범위 = 모든 파일의 (min, max) 합집합.
- **날짜 키 최신 파일이 전체 범위의 95%+ 를 포함** → **누적 모드**.
- 아니면 → **증분 모드**.
- 2.1 표의 판정을 기본값으로 하되, 스크립트 실측과 불일치 시 리포트에 경고하고 실측 우선.

### 3.4 누적 모드
- 날짜 키가 가장 늦은 파일 1개 채택 → 정규화 → `00_corpus/<문집>.xml`.
- 임백호집은 예외적으로 `임백호집_3차완본_20260730.txt` 고정.

### 3.5 증분 모드
- 파일을 (ID 구간 시작) 순으로 정렬, 같은 구간이면 날짜 키 순.
- 빈 파일(Poem 0) 제외, 리포트.
- 순서대로 Poem 단위 병합: `Poem id` 충돌 시 **날짜 키가 나중인 파일 우선**.
- 결과 ID 목록에서 **연속성 검사** → 공백 구간은 `대상데이터_데이터클리닝/태깅_<문집>.txt`의 해당 Poem으로 보충(fill). 보충한 ID를 `reports/00_merge.md`에 명시.
- 대상데이터에도 없는 공백은 "실공백"으로 리포트.
- base 파일(ID 구간 없이 문집 전체를 담는 것, 예: 석주집 김재윤 주차본)이 있으면 그것을 바탕으로 ID 구간 파일들을 덮어씀.
- 결과의 ID 연속성·누락 구간을 리포트.

### 3.6 임백호집 특례
- base = `임백호집_3차완본_20260730.txt`
- `임백호집_임제_김영인(P17367-17397)`, `이연지_…36주차(17537-17572)`, `37주차(17573-17616)` 등 3차완본 ID 범위(P17064~P17767)를 **벗어나는** 추가분만 병합. 범위 내는 완본 우선.

### 3.7 4개 결번 문집
`대상데이터_데이터클리닝/태깅_<문집>.txt`를 그대로 `00_corpus/<문집>.xml`로 복사(정규화만).

## 4. 정규화 (전 문집 공통)

- 인코딩 UTF-8 통일(입력이 cp949/UTF-16이면 변환), 개행 LF.
- 태그 표기 통일: 매뉴얼은 `<Term>`/`<D>`/`<Rhyme>` 대문자, 대상데이터·골드는 소문자 `<term>`/`<d>`/`<rhyme>`. → **소문자로 통일**(대상데이터·골드 기준).
- `<Poem>`, `<Line>`, `<Metadata>`, `<Form>` 등 구조 태그는 현행 유지.
- XML 조각(파일마다 `<?xml?>`·루트 유무 상이) → 문집당 `<Corpus>…</Corpus>` 하나로 감쌈(골드와 동일).
- 깨진 태그(닫힘 없는 `<term>`/`<d>`, `<Couplet>` 불균형 등)는 `00_lint`가 검출 → 리포트, 자동수정 안 함.

## 6. 검증 (수용 기준)

1. `00_lint.md`에 치명 오류(파싱 불가) 0건. 경미 경고는 목록화.
2. 각 `00_corpus/<문집>.xml`이 XML 파서로 로드됨(`<Corpus>` 래핑 후).
3. 문집별 Poem 수가 한국고전종합DB 대비 ±0(가능한 경우) 또는 리포트에 편차 사유.
4. **임백호집**: 통합본 Poem id 집합이 골드 723수를 포함(초과분은 3차완본 이후 추가분). 불일치 시 `00_align_임백호집.md`에 전건 명시.

## 9. 미해결 / 리스크

1. ~~Drive 레이트리밋~~ → **해결**: 사용자가 전체 zip 다운로드 (`4-1. 생성 데이터 [전원]-20260828T021116Z-1-001.zip`, 214파일). `scratchpad/hansi/00_raw/`에 전개 완료.
2. **`.rtf` 처리**: 읍취헌유고 8월1주차~9월2주차(P16805~P16842). 이 구간은 txt/xml본에 없으므로 **포함 필수**. Python `striprtf`로 추출 (pip 설치). `.rtf.docx`(0수, RTF→DOCX 변환물)는 제외.
3. **파일명 인코딩**: zip이 자모 분해(NFD)로 전개됨 — 모든 파일 조작은 Python(`unicodedata.normalize('NFC')`)으로, bash 직접 glob 금지.
4. **공백 구간**: 어우집 P12677~P12702, 지봉집 P18068~P18086 등 — 자동 채우지 않고 리포트. 원 코퍼스(대상데이터)에서 보충할지는 사용자 판단.
5. **Poem 수 기준선**: 한국고전종합DB 대조는 수작업. 1차엔 통합본 내부 일관성만 확인, 편차는 리포트.
